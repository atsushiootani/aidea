# 計画: Tool 概念導入 (Phase 1)
作成日: 2026-04-08

## 目的
SPEC.md の Phase ロードマップに沿って、Phase 1 「Tool 概念の導入」を完了する。
既存の各機能 (Filer/Skills/Commands/MCPs/Terminal/Web/Preview) を Tool として抽象化し、
ペイン⇄Tool のマッピングを LayoutConfig で管理できるようにする。
Models / Services / Views をツール別サブディレクトリに再編する。

最終目標 (Phase 5 まで) のうち、本計画では **レイアウトはまだ 4 ペイン固定** とし、
動的分割・ドラッグ&ドロップ・永続化は後続フェーズに委ねる。

## 技術的注意点
- **Tool は kind (種別) と instanceID で一意化** する。Phase 1 では各 kind 1 インスタンス固定だが、
  Phase 5 を見据えて型は `ToolID(kind: ToolKind, instance: Int)` で定義しておく
- **ToolState はクラス参照** にする。ペイン移動で View が再生成されても状態が保持されるよう、
  状態オブジェクトは ToolRegistry が保持する
- **WorkspaceState から各 Loader を切り出す**: WorkspaceState は projectRoot のみ集中管理し、
  各 Tool のローダ/ウォッチャは ToolState の中に閉じ込める
- **既存ファイルの移動はファイル単位**: Xcode は synced groups なのでディスク上の mv で OK
- **Terminal だけは状態を持たない**: PTY を毎回新規起動する。ペインを閉じると履歴は消える
- **Tool は SwiftUI View を返すファクトリにする**: `ToolKind.view(state:)` で対応 View を生成
- **Tool 切替 UI**: ペイン上部のタブヘッダの右側に「+」ボタン → メニューで kind を選択して切替
  (Phase 1 では追加でなく置換とする)
- **Phase 1 で UI に出す機能**: 「右クリックでこのペインのツールを変更」 のみ。
  ドラッグ&ドロップは Phase 3 まで保留

    - `protocol ToolState: AnyObject` を定義 (Phase 4 で永続化エンコーディング用に拡張予定)

  - 依存: なし

- [ ] タスク3: 各 Tool の ToolState クラスを作成
  - 受け入れ基準:
    - `Tools/Filer/FilerToolState.swift` (展開フォルダ集合 + selectedFile)
    - `Tools/Skills/SkillsToolState.swift` (loader + 選択 + 開閉)

    - `Tools/Mcps/McpsToolState.swift`

    - `Tools/Web/WebToolState.swift` (URL のみ)

- [ ] タスク4: ToolRegistry を実装

    - `func view(for: ToolID) -> some View` (kind に応じた SwiftUI View を返す)
    - WorkspaceState を保持し、各 ToolState に注入できる
