# 計画: Session first-class object + 3 つのアクティブ概念 + ライフサイクルコールバック
作成日: 2026-04-10

## 目的
ADR 0013 に基づき、Session を first-class object に昇格させ、
Active Pane / Active Tab / Active Session の 3 階層アクティブ概念を導入する。
ライフサイクルコールバック (didBecomeActive / didResignActive) により
フォーカス管理を各 Session の自己責務に移し、集中管理の switch 分岐を廃止する。

## 技術的注意点
- **Active Session は computed property**: `activePane?.tabs[activePane.activeIndex]`。
  stored property として独立管理せず、Active Pane + Active Tab から導出する
- **activeSessionID の変更検知**: computed のため didSet が使えない。
  activePaneID / Pane.activeIndex の変更時に前回値と比較して手動検知する
- **activeHistory**: 導出された activeSessionID の変化を検知して蓄積する (openPreview のルーティングに使用)
- **focusableView は Session に持たせる**: SessionState ではなく Session のプロパティ。
  子ビューが動的に更新する仕組みは維持
- **FocusCatcherView**: 純 SwiftUI コンテンツ (MarkdownPreview view モード等) は
  FocusCatcherNSView を背景に配置して focusableView に報告。
  AppKit 系コンテンツは本来の NSView (NSTextView, WKWebView 等) を報告
- **DispatchQueue.main.async**: ライフサイクルコールバック内で makeFirstResponder を呼ぶ場合は
  SwiftUI update サイクル外で実行する
- **永続化**: activePaneID + 各 Pane.activeIndex + Pane.id で 3 つの Active を完全復元。
  Pane.id を LayoutNodeSnapshot に追加する必要あり
- **破壊的変更**: SessionRegistry の内部構造 (states dict → sessions 配列)、
  SessionState プロトコル (focusableView 削除 + ライフサイクル追加) が変わるため全参照箇所を修正

## タスク一覧

- [ ] タスク1: Session クラスを定義
  - 受け入れ基準:
    - `Tools/Session.swift` に `@Observable final class Session: Identifiable` を定義
    - プロパティ: `id: SessionID`, `state: any SessionState`, `focusableView: NSView?`
    - メソッド: `activate()` → `state.didBecomeActive(session: self)`,
      `deactivate()` → `state.didResignActive(session: self)`
  - 依存: なし

- [ ] タスク2: SessionState プロトコルをリファクタ
  - 受け入れ基準:
    - `SessionState` から `focusableView` プロパティを削除
    - `func didBecomeActive(session: Session)` を追加 (デフォルト実装: 空)
    - `func didResignActive(session: Session)` を追加 (デフォルト実装: 空)
    - 既存の各 SessionState (Filer/Terminal/Web/Kit/Preview) がコンパイルを通る
  - 依存: タスク1

- [ ] タスク3: 各 SessionState に didBecomeActive を実装
  - 受け入れ基準:
    - **FilerSessionState**: `session.focusableView` を `makeFirstResponder`
    - **TerminalSessionState**: 同上
    - **WebSessionState**: 同上
    - **KitSessionState**: `isFocused = true` (SwiftUI @FocusState)
      → KitSessionState に `@FocusState` 相当の仕組みを持たせるか、
        KitSessionView が Session.activate() をフックして isFocused をセットする
    - **PreviewSessionState**: `session.focusableView` があれば `makeFirstResponder`、
        なければ何もしない (FocusCatcher 経由で focusableView は常に non-nil になる想定)
    - 全 Session でフォーカスが正しく切り替わる
  - 依存: タスク2

- [ ] タスク4: SessionRegistry を sessions 配列ベースに書き換え
  - 受け入れ基準:
    - `states: [SessionID: any SessionState]` を `sessions: [Session]` に変更
    - `session(for: SessionID) -> Session?` メソッド追加
    - `createSession(tool:instance:) -> Session` メソッド追加 (Session + SessionState を生成して配列に追加)
    - `destroySession(_ id: SessionID)` メソッド追加 (配列から除去)
    - `peekState(for:)` は `session(for:)?.state` で代替
    - `refocusActiveSession()` を削除 (Session.activate() に移行)
    - `focusableView(for:)` を削除 (Session.focusableView に移行)
    - 既存の全呼び出し箇所が新 API に切り替わる
  - 依存: タスク1

- [ ] タスク5: Active Pane 概念の導入
  - 受け入れ基準:
    - `SessionRegistry` に `activePaneID: UUID?` を追加 (Pane.id を参照)
    - `activePane: Pane?` computed property 追加 (`layout.allPanes.first { $0.id == activePaneID }`)
    - `activeSessionID: SessionID?` を computed property に変更
      (`activePane?.activeSessionID`)
    - 既存の `activeSessionID` の stored property 用法を全て移行
    - `activePaneID` の didSet で前回/今回の activeSessionID を比較し、変わっていたら
      旧 session.deactivate() + 新 session.activate() を呼ぶ
  - 依存: タスク4

- [ ] タスク6: Pane.activeIndex 変更時のライフサイクル発火
  - 受け入れ基準:
    - `Pane.activeIndex` の didSet で、このペインが Active Pane なら
      旧 activeSessionID → deactivate、新 activeSessionID → activate を呼ぶ
    - Pane が SessionRegistry (または layout) への参照を持つか、
      NotificationCenter 経由でイベントを発火する
    - Cmd+Shift+[ でタブ移動した際にフォーカスが正しく切り替わる
  - 依存: タスク5

- [ ] タスク7: activeHistory の更新ロジック移行
  - 受け入れ基準:
    - activeSessionID (computed) が変わったタイミングで activeHistory に追加
    - タスク5・6 の activate/deactivate 呼び出しと同時に履歴を更新
    - openPreview のルーティング (非 caller ペインを履歴から探す) が既存通り動作する
  - 依存: タスク5, タスク6

- [ ] タスク8: PaneView / ContentView / AideaApp のフォーカス管理を移行
  - 受け入れ基準:
    - ContentView の `onChange(of: registry.activeSessionID)` + `refocusActiveSession()` を削除
    - PaneView のタブクリック: `registry.activePaneID = pane.id` + `pane.activeIndex = index` だけセットする
      (activate/deactivate はタスク5・6 で自動発火)
    - AideaApp の moveTab / movePane / focusTool / splitCurrent / closeCurrentTab を
      activePaneID + Pane.activeIndex ベースに書き換え
    - 全操作でフォーカスが正しく追従する
  - 依存: タスク5, タスク6, タスク7

- [ ] タスク9: 子ビューの focusableView 報告を Session 経由に変更

    - 子ビュー (NSTextPreview / EditableTextView / DrawioStaticView / FocusCatcherView 等) が
      `session.focusableView = nsView` を直接セットする
    - 子ビューに Session への参照を渡す経路を確保
      (View → Session をパラメータとして渡すか、@Environment で注入)
    - 子ビューのコンテンツ切り替え時に focusableView が正しく更新される
  - 依存: タスク1, タスク4
