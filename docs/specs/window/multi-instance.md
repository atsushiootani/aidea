# 複数インスタンス (マルチプロセス) 起動

別々のリポジトリを同時に開くための起動モデル。基盤となる設計判断は [ADR 0030](../../decisions/0030-multiprocess-one-repo-per-process.md) を参照。

## 起動モデル

- **1 プロセス = 1 ウィンドウ = 1 リポジトリ**を不変条件とする。
- 複数のリポジトリを同時に開くときは、リポジトリごとに**別プロセス**を起動する (マルチプロセス)。
- 各プロセスは独立したワークスペース状態・セッション・コンパニオン枠を持つ。状態は開いているリポジトリの `.aidea/` 配下にプロジェクト単位で保存されるため、別リポジトリ同士は干渉しない。
- **ウィンドウを閉じるとそのプロセスも終了する**。1 プロセス = 1 ウィンドウのため、ビューだけ消えてプロセスが残る紛らわしい状態を作らない。終了時に排他ロック (後述) を解放する。
- **ウィンドウタイトルにリポジトリ名を表示する** (`Aidea — <リポジトリ名>`)。複数プロセスは Dock アイコン上で 1 つに集約されるため、タイトルで見分けられるようにする。macOS の Cmd+Tab はアプリ単位で集約され別名にできないが、Cmd+` / App Exposé / Dock のウィンドウ一覧ではタイトルで区別できる。

## 新しいリポジトリを開く

UI 上ではプロジェクトルートを**「ワークスペース」**と呼ぶ (Filer が扱う通常のファイルディレクトリと紛らわしいため「ディレクトリ」とは呼ばない。内部実装名 `Workspace` / URL スキーム `open-workspace` とも一致する)。

- **「最近開いたワークスペースを開く」(⌘⇧O)**: 最近開いたリポジトリ (MRU) の一覧 (ランチャー) を出して選ばせる。選んだリポジトリは新しいプロセスで開く (現在のウィンドウはそのまま継続)。
- **「ワークスペースを開く」(⌘O)**: ディレクトリ選択ダイアログでリポジトリを選ぶと、**常に新しいプロセス**でそのリポジトリを開く。現在のウィンドウのリポジトリは差し替えない。
- **URL スキーム** `aidea://open-workspace?path=<percent-encoded-abspath>`: 指定パスのリポジトリを開く。未割り当ての (まだリポジトリを持たない) プロセスがあればそのプロセスで開き、なければ新プロセスを起動する。
  - 既存の `aidea://open?path=...` (ファイルを Preview で開く) とは `host` 部 (`open-workspace` / `open`) で区別する。

## 素起動時の挙動 (MRU)

- Dock / Finder からの起動など、開くリポジトリが指定されないときは、**最近開いたリポジトリ (MRU: Most Recently Used) の一覧**を提示して選ばせる。
- MRU の更新は**最後勝ちによる取りこぼしを避ける**。各プロセスが終了時にリストを丸ごと上書きするのではなく、保存時に現在の保存値を読み直してから自リポジトリを先頭へ繰り上げる (read-merge-write)。これにより、複数プロセスが同時に動いていても他プロセスが開いたリポジトリが MRU から消えない。
- 存在しなくなったリポジトリ (ディレクトリ削除済み) は提示時に一覧から除外する。

## 同一リポジトリの排他と前面化

- 同じリポジトリを**二重に開くことは禁止**する。既に開いているプロセスがあれば、新規プロセスは起動せず、**黙って既存プロセスを前面化**する (確認ダイアログや通知は出さない)。
- 排他は、各リポジトリの `.aidea/.instance.lock` を所有権の単一情報源として行う。
  - lock には所有プロセスの識別情報と、前面化要求を届けるための一意トークンを記録する。
  - lock は**取りこぼしなく 1 プロセスだけが取得**できる方式 (排他生成) で扱う。
  - 異常終了で lock が残った場合は、記録されたプロセスがもう生きていない (かつ Aidea でない) ことを確認してから無効と判定し、奪取する。
- 既存プロセスの前面化は、lock のトークンを宛先にした通知で要求する。トークンで宛先を特定することで、別リポジトリのプロセスを誤って前面化しない。
- リポジトリの同一判定は、表記揺れ (相対パス・シンボリックリンク・末尾スラッシュ) を吸収するため**正規化した絶対パス**で行う。

### lock ファイルの所在

- 置き場所は各リポジトリの `.aidea/.instance.lock`。`.aidea/` はローカル専用でバージョン管理外 ([ADR 0026](../../decisions/0026-use-git-info-exclude-instead-of-gitignore.md))。
- lock はファイラ表示・FSEvents 監視の対象から除外する (取得・解放のたびに監視ノイズを出さない)。
- `.aidea/` に書き込めないリポジトリ (読み取り専用など) では排他できないため、その場合は排他を諦めて起動を続行する (多重起動を許容する)。

## 共有リソースの扱い

複数プロセスが同時に動いても安全であることが確認済み / 要注意な共有リソース:

- **VOICEVOX** (読み上げ): 複数プロセスが同一の読み上げサーバを共有してよい。ただし複数プロセスの発話が混ざったときに「どのリポジトリのコンパニオンが喋ったか」は区別されない (出所表示は今後の課題)。
- **ユーザ全体の設定** (`~/.claude/` のエージェント / コマンド / スキル定義など): 全プロセスが読み取りで共有する。あるプロセスが編集すると他プロセスの表示と一時的に食い違うことがある。

## Always / Never

- **Always**: 別リポジトリを開くときは新プロセスを起動する。同一リポジトリは既存を前面化する。リポジトリの同一判定は正規化済み絶対パスで行う。MRU は read-merge-write で更新する。
- **Never**: 同一リポジトリを 2 プロセスで同時に開かない。グローバルなキーイベント監視 (全プロセスに届くもの) を追加しない (プロセスを跨いだキー競合の原因になる)。現在のウィンドウのリポジトリを途中で別リポジトリに差し替えない。
