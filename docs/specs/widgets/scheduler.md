# 定時スケジューラ (Scheduler)

> Aidea が設定した時刻・曜日に、指定 Companion のセッションへ定型コマンドを「ユーザが入力したかのように」自動送信する汎用の定時スケジューラ

ヘッダ常駐 widget。任意の「時刻 + 曜日 + 送信先 Companion + コマンド」を**ジョブ**として複数登録でき、各ジョブを定刻にアプリ内で発火させる。朝メモ生成 (`/cc.morning` を concier-chan へ) はこのスケジューラの 1 ジョブとして実現する代表例だが、用途は朝ルーティンに限らない。

発火の送信経路は [frontchannel.md](../frontchannels/frontchannel.md)（PTY への送信）。定時発火 + widget という構成は [remind.md](../backchannels/remind.md) と似るが、**発火源・発火先・繰り返し・取りこぼし時の扱いが異なる**。

| 観点 | Remind | 定時スケジューラ (本仕様) |
|---|---|---|
| トリガ源 | Companion が書いたファイル（ファイル名=絶対時刻） | **アプリ内スケジューラ**（設定の時刻で毎日 / 曜日条件） |
| 繰り返し | 1 回だけ（絶対時刻） | **毎日（曜日条件つき）を複数ジョブ** |
| 発火先 | SpeechQueue（音声読み上げ） | **指定 Companion セッションへプロンプト送信** |
| 取りこぼし時 | 過去なら読み上げずスキップ | **自動実行せず「未実行」を widget で通知** |

---

## 概要

ユーザの定型作業（例: 朝メモ生成）を、`claude -p` のヘッドレス実行ではなく **Aidea 上の対話セッション**で回すための仕組み。アプリが常駐している前提で、各ジョブの設定時刻に指定 Companion へコマンドを送信する。

ヘッドレス実行を避けることで対話セッション扱いとなり、サブスク枠で動作する（プログラム実行向けの別課金区分を回避できる）。Mac 自体の起動維持は別系統（`pmset` による定刻 wake、`quickmemo/general/system/mac-wake.md`）が担う。

### 設計原則

1. **発火点はアプリ内** — cron / launchd 等の外部スケジューラに依存しない。Aidea が起動中であることを前提とする（[remind.md](../backchannels/remind.md) の原則 4 と同じ）。
2. **IDE にロックインしない** — 送信する中身は単なるスラッシュコマンド文字列。Aidea が無くても素のターミナルで同じコマンドが叩ける（コマンド本体はユーザースコープに置かれる前提）。
3. **取りこぼしは自動補完しない** — アプリ未起動などで定刻を逃した場合、勝手に遅延実行せず、ユーザに「未実行」を提示して**手動実行に委ねる**。
4. **設定はファイルで宣言** — ジョブ（時刻・曜日・送信先 Companion・コマンド・有効無効）は設定ファイルで持ち、コードを触らず追加・変更できる。
5. **汎用** — 特定用途（朝ルーティン）に固定しない。朝メモはあくまで初期ジョブの 1 例。

## フロー

```
[定刻発火（オンタイム）]
1. アプリ常駐中、あるジョブの設定時刻に到達
2. そのジョブが 有効 (enabled) かつ 当日が曜日条件を満たすか判定
3. ジョブの送信先 Companion のセッションを取得
   - 起動済み → そのまま使用
   - 未起動   → セッションを起動し、Claude 初期化完了 (ready) を待つ
4. ready 後に そのジョブの prompt を「文字列 + Enter」で送信
5. 状態ファイルに「そのジョブを当日実行済み」を記録
```

```
[取りこぼし（オフタイム）]
1. アプリ起動時、各ジョブについて状態ファイルと現在時刻を照合
2. 「当日まだ未実行」かつ「設定時刻を過ぎている」かつ「有効」なら
   → 自動実行はしない
   → そのジョブを widget で「未実行」状態にして通知（手動実行を促す）
3. ユーザが widget から該当ジョブの「今すぐ実行」を押すと、定刻発火と同じ送信を行い、
   当日実行済みを記録する
```

## 設定ファイル

ユーザが編集する宣言的設定。**JSON 形式**とする（外部依存を SwiftTerm のみに保つ方針のため YAML パーサを導入しない。アプリの既存永続化も JSON 指向）。

### パス

```
.aidea/config/scheduler.json
```

### 形

ジョブの配列を持つ。

| キー | 型 | 意味 |
|---|---|---|
| `jobs` | object[] | スケジュールジョブの配列 |

各ジョブ (`jobs[]`):

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `id` | string | （必須） | ジョブ識別子。状態ファイルのキー・重複送信判定に使う（一意） |
| `name` | string | `id` と同じ | 表示名（widget / popover 用） |
| `enabled` | bool | `true` | ジョブの有効 / 無効 |
| `time` | string | （必須） | 発火時刻 `HH:mm`（システムのローカルタイムゾーン） |
| `weekdays` | int[] | `[0,1,2,3,4,5,6]` | 発火する曜日（0=日 〜 6=土）。省略時は毎日 |
| `companionIndex` | int | （必須） | 送信先 Companion index（`0..8`） |
| `prompt` | string | （必須） | 送信するプロンプト文字列（スラッシュコマンドでも任意の指示文でもよい） |

### 初期ジョブ（朝メモ）の例

```json
{
  "jobs": [
    {
      "id": "morning",
      "name": "朝ルーティン",
      "enabled": true,
      "time": "08:00",
      "weekdays": [0, 1, 2, 3, 4, 5, 6],
      "companionIndex": 6,
      "prompt": "/cc.morning"
    }
  ]
}
```

- 設定ファイルが存在しない場合は**ジョブ無し**（何も発火しない）として扱う。初期セットアップで上記 morning ジョブを既定配置するかは実装時に判断する。
- 不正値（時刻パース不可・index が範囲外・`id` 重複・必須欠落）は警告ログを出し、当該ジョブをスキップする（他ジョブには影響させない）。

## 状態ファイル

自動管理。ユーザは通常編集しない。

### パス

```
.aidea/state/scheduler.json
```

### 形

| キー | 型 | 意味 |
|---|---|---|
| `lastRun` | object | ジョブ `id` → 最後に送信した日付 `YYYY-MM-DD`（ローカルタイムゾーン）のマップ |

```json
{ "lastRun": { "morning": "2026-06-06" } }
```

- ジョブの「本日実行済み」判定は `lastRun[id] == 今日の日付`。
- 手動実行・定刻発火のどちらでも、送信したらそのジョブ `id` を当日日付で更新する。

---

## スケジューリング挙動

- アプリ起動中、各ジョブの設定時刻に**毎日**発火する。日をまたいでも次回分が登録され続ける。
- 発火時に `enabled` と `weekdays`（当日が含まれるか）を確認し、満たさなければ送信しない（状態も更新しない）。
- 設定ファイルの変更は次回起動時に反映する（ランタイム再読込の要否は実装時に判断。初版は起動時読込で可）。
- **スリープ復帰時の張り直し**: アプリ内タイマーはシステムスリープ中は時間が進まないため、長い遅延（翌日発火など）はスリープを跨ぐとずれる。システム復帰を検知したら、取りこぼし判定を再計算し、各ジョブの次回発火を**現在時刻基準で再登録**する（`pmset` で定刻前に wake → 復帰時に当日設定時刻の新規タイマーを張り直して正しく発火させる）。

---

## 発火先（セッション送信）

- 送信はジョブの `companionIndex` の Companion セッションに対して行い、その Companion として扱う（表情・ビジー表示も同じ）。
- セッションが**未起動**の場合は起動し、Claude の初期化完了 (ready) を待ってから送信する（[handoff.md](../backchannels/handoff.md) の「未起動なら起動して ready 後に送る」挙動と同じ）。
- 送信内容はジョブの `prompt` 文字列に改行（Enter 相当）を付与して送る。

## UI: SchedulerView（ヘッダ常駐 widget）

[widgets/README.md](./README.md) の `WidgetView` 内に、**`RemindView`（カレンダー）の左隣**に配置する。`RemindView` と同系統の「アイコン + テキスト + Popover」UI とする。

### WidgetView 内の並び

```
WidgetView
├─ SchedulerView       ← 今回追加（定時スケジューラ。RemindView の左）
├─ RemindView          (リマインド。カレンダー)
├─ QuickMemoButton     (クイックメモ)
└─ TimerView           (ポモドーロ)
```

[../aspects/view-hierarchy.md](../aspects/view-hierarchy.md) の AppHeaderView 階層図も同期更新する。

### ヘッダ表示要素

| 要素 | 内容 |
|---|---|
| アイコン | 時計の SF Symbol（例: `clock`）。クリックで Popover を開く |
| ラベル / 状態 | 下記「状態表示」に従う（全ジョブを俯瞰した代表状態） |

### 状態表示（widget ラベル）

複数ジョブの状態を 1 つのラベルに集約する。優先順位は **未実行（要対応） > 次回待ち > 全停止**。

| 状態 | 条件 | 見え方（目安） |
|---|---|---|
| **未実行（要対応）** | いずれかのジョブが「当日未実行・時刻超過・有効」 | ⚠ 警告色で「未実行 N」。クリックで手動実行を促す |
| **次回待ち** | 要対応ジョブが無く、有効ジョブが 1 件以上 | 直近の次回発火 `HH:mm` をグレー表示 |
| **全停止** | 有効ジョブが 1 件も無い / ジョブ無し | グレーで「停止中」 |

### Popover: SchedulerPopoverView

`RemindPopoverView` と同じスタイル（`.popover` 装飾）で表示する。登録ジョブを一覧し、**追加・編集・削除**も popover 内で完結する。

```
┌─ SchedulerPopoverView ──────────────────┐
│  定時スケジューラ              [＋ 追加] │
│                                         │
│  ┌─ ジョブ一覧 ─────────────────────────┐ │
│  │ ⚠ 朝ルーティン  08:00 毎日           │ │
│  │   → concier-chan / /cc.morning       │ │
│  │   本日 未実行  [今すぐ実行][✎][🗑][ON]│ │
│  │ ─────────────────────────────────── │ │
│  │ ✓ （別ジョブ）  19:00 平日           │ │
│  │   本日 実行済み      [今すぐ実行]…[ON]│ │
│  └──────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

| 要素 | 内容 |
|---|---|
| タイトル | 「定時スケジューラ」＋ **「＋ 追加」ボタン**（押すと編集フォームを新規モードで展開） |
| ジョブ行 | `name` / `time` / 曜日 / 送信先 Companion / `prompt` / 本日の実行状態 |
| 今すぐ実行 | 押すと定刻発火と同じ送信を行い、当日実行済みを記録。**未実行（要対応）時の主動線** |
| 編集（✎） | 押すと該当ジョブを編集フォームに展開する |
| 削除（🗑） | 押すと該当ジョブを config から削除する |
| ON/OFF トグル | ジョブ単位の `enabled` 切替（設定ファイルに反映） |
| 空状態 | ジョブが 1 件も無いとき「ジョブなし」と表示 |

#### 編集フォーム: SchedulerJobEditView

「＋ 追加」または行の「編集」で、**同じ popover 内**に展開する（別シートは開かない）。以下を編集して「保存」で `config` に反映、「キャンセル」で一覧へ戻る。

| フィールド | UI | 備考 |
|---|---|---|
| 名前 (`name`) | テキスト入力 | 必須（空だと保存不可） |
| 時刻 (`time`) | 時刻ピッカー（時・分） | `HH:mm` として保存。不正入力が起きない |
| 曜日 (`weekdays`) | 日〜土の 7 トグルチップ | 1 つ以上選択必須 |
| 送信先 (`companionIndex`) | Companion ピッカー（`0: main-chan` 〜 `8: quick-chan` を名前表示） | CompanionStore の名前を表示 |
| プロンプト (`prompt`) | テキスト入力 | 必須。スラッシュコマンドでも任意の指示文でもよい |
| 有効 (`enabled`) | トグル | |

- 新規ジョブの `id` は自動採番する（`job-<8桁>`）。既存編集時は `id` を保持する。
- 保存可能条件: 名前・プロンプトが非空 かつ 曜日が 1 つ以上。
- ESC で閉じる。
- 専用グローバルショートカットは初版では設けない。

## 境界

### Always

- 発火時刻・日付はシステムのローカルタイムゾーンで解釈する。
- 送信は各ジョブの `companionIndex` の Companion セッションに対して行い、未起動なら起動して ready 後に送る。
- 当日実行済みは状態ファイルの `lastRun[id]` で表現し、定刻発火・手動実行のどちらでも更新する。
- 取りこぼし（定刻時にアプリ未起動など）は **widget の「未実行」表示で通知し、自動実行はしない**。
- 不正・重複・必須欠落のジョブは警告ログでスキップし、他ジョブの動作は止めない。

### Never

- cron / launchd 等の外部スケジューラを Aidea から設定しない（発火点はアプリ内。Mac の wake 維持は `pmset` の別系統で、本機能はそれを設定・管理しない）。
- 取りこぼしを勝手に遅延実行しない（ユーザの手動実行に委ねる）。
- ヘッドレス（`claude -p`）でジョブを起動しない（対話セッションで回す）。
- 同一ジョブを同一日に二重送信しない（`lastRun[id] == 今日` の間は定刻発火しない）。
- ジョブの ON/OFF を `workspace.json` には保存しない（設定ファイル `scheduler.json` の `enabled` が単一情報源）。
