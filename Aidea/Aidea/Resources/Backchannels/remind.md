# リマインド機能

このファイルを読んでいる場合、あなたは予定や作業のリマインドをファイル経由で Aidea に予約する責務を持ちます。

スケジュール (Google Calendar 等) の取得手段は問いません。MCP / 自前のメモ / ユーザからの口頭指示など、任意の方法で「いつ・何を伝えたいか」を知り、それをファイルとして書き出してください。指定時刻に Aidea があなた (= 同じ Companion) として VOICEVOX で読み上げます。

## ファイルの書き出し先

```
.aidea/backchannels/<N>/remind-{YYYYMMDDTHHmmss}.txt
```

- `<N>`: あなたの Companion index。`.aidea/claude/companions/<N>/instructions.md` のパス `<N>` をそのまま使ってね
- `{YYYYMMDDTHHmmss}`: **トリガ時刻 (発火させたい時刻)**。システムのローカルタイムゾーンとして 14 桁固定で書く
- ディレクトリがなければ作成してね (`mkdir -p` 相当)
- 既存ファイルは上書きしない (時刻 + 内容が偶然衝突した時はファイル名のサフィックスで避けるか、別な秒数にずらしてね)

## ファイルの中身

speech ファイルと同じフォーマットだよ。

- 1 行目: 読み上げスピーカーIDを数値のみで指定 (省略可、省略時はデフォルトスピーカー)
- 2 行目以降: 読み上げテキスト本文
- 英単語はカタカナに変換すること
- 記号は省略すること
- 句読点ではスペースを開けて、ちゃんと区切ること

例 (Companion 6 が「14:00 の打ち合わせを 1 分前にリマインドしたい」ケース):

```
// .aidea/backchannels/6/remind-20260527T135900.txt
2
ご主人 あと 1 分で 打ち合わせ だよ 準備してね
```

## 計算手順

ユーザから「N 分前にリマインドして」と頼まれたとき:

1. 予定の開始時刻を確認する (ユーザ発言 / カレンダー取得結果から)
2. `trigger = 開始時刻 - N 分` を計算する
3. `trigger` をローカルタイムゾーンの `YYYYMMDDTHHmmss` 形式に整形する
4. 上記パスにファイルを書き出す
5. ユーザに「OK、 HH:mm に音声でお知らせするよ」のように返事をする (speech 経由で OK)

複数タイミングを一括で頼まれた場合 (例: 60 分前と 10 分前と直前)、それぞれ別ファイルとして書き出してね。

## キャンセル / 変更

ユーザから「さっきのリマインドキャンセルして」「もう 10 分早めて」等を依頼されたら:

- キャンセル: 該当 `remind-{ts}.txt` を `rm` で削除する
- 変更: 旧ファイルを削除して新しい時刻で新規作成する

Aidea が FSEvents の削除イベントを検知してタイマーを破棄するから、削除すれば確実にキャンセルされるよ。

## 発火後について

Aidea がトリガ時刻にファイルを読み上げると、ファイル名末尾を `.fired.txt` にリネームする (例: `remind-20260527T135900.fired.txt`)。これは履歴として残るので、削除しないでね。

## 注意

- 過去のタイムスタンプで書き出しても発火しない (Aidea 側でスキップする)
- リマインド機能がユーザ操作で OFF にされている可能性があるよ。OFF の間に書き出したファイルも、ON に戻ったときに再スキャンで取り込まれる
- 音声内容に予定の固有名や URL を全部含めないでね (VOICEVOX が崩れることがあるので、要点だけ短く)
