# aidea.round-table — 円卓会議

企画/設計を複数キャラで多視点議論し、**司会役がまとめる**汎用スキル。
司会役は他キャラに **Aidea のハンドオフ機能** で意見を求める。

**参加キャラ・index・ハンドオフ順・各役割は、同じディレクトリの [`cast.md`](./cast.md) を SSoT とする。**
以下の本文でキャラ名・役割が出る箇所は `cast.md` の定義に読み替える。`cast.md` が無い場合は、司会役がご主人に参加者と役割を尋ねてから進める。

> 自分が司会役でない場合: 司会役に handoff してこのスキルを起動させる。

## 引数

`$ARGUMENTS`: 議題 (省略可)。省略時はご主人に議題を尋ねる。

## 進め方

### Phase 0: 議題確認 (必要に応じて)

司会役は議題が議論可能なほど明確かを判断する。曖昧なら以下をご主人に**対話で**確認する (ハンドオフは使わない)。

- 何を決めたいのか / 制約 (時間・コスト・既存資産) / ゴールと成功基準 / スコープ / 前提・既知の事実

明確なら Phase 0 はスキップ可。

### Phase 1: 議題化

司会役が議題・論点 (チェックリスト)・前提/制約を 1 メッセージで提示し、ご主人に承認を求める。
承認後、**議論ディレクトリ**を作ってから Phase 2 へ。

```
.aidea/widgets/round-table/<YYYYMMDDTHHmmss>-<slug>/
├── topic.md       ← 議題・論点・制約 (会議中は変更しない)
├── log.md         ← 司会役が更新する全体タイムライン
└── opinions/      ← 各キャラの意見全文 (1 発言 1 ファイル r<N>-<role>.md)
```

このパスを会話履歴で保持する (以降 TOPIC_DIR)。speech 機能が有効なら、Phase 2 の最初のハンドオフ直前に開始宣言を `.aidea/backchannels/<司会の index>/speech-{timestamp}.txt` に書く。

### Phase 2: ラウンド (繰り返し)

1 ラウンド = `cast.md` のハンドオフ順に各キャラへ意見を求める。

- 司会役は **1 件ハンドオフを書いたらターン終了** (返信待機ループは作らない / handoff.md の規約)。
- 各キャラの返信が Aidea から「.aidea/backchannels/<N>/handoff-*.json の作業をやってね」で届いたら、次のキャラへハンドオフ。

#### ハンドオフ JSON (送信)

`.aidea/backchannels/<司会の index>/handoff-{timestamp}.json`:

```json
{ "from": <司会 index>, "to": "<宛先キャラ名 or index>", "task": "round-table", "message": "<下記テンプレ>" }
```

`message` は**全文を埋めず、ファイルパスで参照させる**。TOPIC_DIR の絶対パス・議題要約・これまでの意見一覧 (1 行要約 + `opinions/r*-*.md`) ・「あなたへの依頼」(役割・読むべきファイル・意見を `opinions/r<N>-<role>.md` に全文保存・司会へ返信) を含める。

#### 各キャラの意見保存と返信

- 意見全文は `TOPIC_DIR/opinions/r<N>-<role>.md` に保存 (frontmatter: round/role/character/references/last_updated)。
- 司会への返信は `.aidea/backchannels/<自分の index>/handoff-{timestamp}.json` (`task: "round-table-reply"`)。message は意見ファイルパス + 1 行要約 + 参照した既出意見のみ。意見なしなら「意見なし」とだけ書き、ファイルは作らない。

#### 司会役の状態管理

`TOPIC_DIR/log.md` を SSoT として、返信が届くたび該当ラウンド行を追記。会話履歴には TOPIC_DIR パスのみ保持し、詳細は log.md から読み返す。返信受信時は「意見なし」かを判定 (終了判定用)、次の役割へハンドオフ。最後の役割から返信が来たらラウンド終了 → Phase 3。

### Phase 3: 終了判定

- 全員「意見なし」→ Phase 4
- 1 体でも新規意見 → 次ラウンドで Phase 2 を繰り返す
- R5 上限 / ご主人が「もう終わって」→ Phase 4

### Phase 4: まとめ

司会役は**全 `opinions/*.md` を読み返してから**結論を提示する (要約だけでまとめない)。

1. ご主人へチャットで「採用 / 却下 / 保留 / 残った懸念」を引用元 (`opinions/r<N>-<role>.md`) 付きで提示
2. `TOPIC_DIR/log.md` のステータスを「完了」にし `## 結論` を追記
3. **`TOPIC_DIR/conclusion.md` を独立資料として書き出す** (ご主人が後で読み返し最終判断する用)。構成: ①議題と最終スコープ ②議論で出た全アイデアと判断 (🟩採用/🟧採用(修正)/🟨保留/🟥却下 + 理由 + 引用元) ③採用案の実装プラン (そのまま実装できる粒度) ④却下まとめ ⑤保留 ⑥残った懸念 ⑦次に決めること。**②と③は必ず両方書く**。テンプレ類はコピペ可能な全文で。
4. speech 有効なら終了宣言を speech ファイルに書く

## 守ること

- ハンドオフ送信側は返信待機ループを作らない (1 件書いたらターン終了)
- 各キャラの役割が混ざらないようメッセージで明確に役柄指定する
- Phase 2-3 は自走 (ご主人に都度確認しない)。Phase 0/1 と Phase 4 のみご主人と対話
- 同じ意見が繰り返されたら司会役の判断で早期終了して良い
- ハンドオフ JSON は削除しない (履歴として残す)
- 意見の本体は message に書かず `opinions/r<N>-<role>.md` に保存。message は 1 行要約 + パスのみ
- 各キャラは他キャラ意見の 1 行要約だけで判断せず、反論前に原文を読む

## 引数なしで起動された場合

ご主人に「議題は何にしますか?」と尋ねて Phase 0 に入る。
